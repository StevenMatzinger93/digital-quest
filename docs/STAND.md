## Werkbank-Umsetzung – Phase 1 erledigt (28.09.2026)
- **Interaktionskern getrennt**: neues Modul `dev/src/circuit-ui.js` (`window.DQCircuit`), ansichtsneutral, ohne DOM/Rendering. Enthaelt Schaltungszustand (`layout`, `locked`, `sel`, `wireStart`, `tool`, `probes`, `drag`) und die Bedienlogik: Bauteil hinzufuegen (freier Rasterplatz, ID-Vergabe), ziehen (Raster/Flaeche), drehen, loeschen (gesperrte Startbauteile bleiben), Leitung ziehen, Schalter/Taster betaetigen, Messspitzen, Tastatur (Entf/R/Esc). Renderer melden nur abstrakte Ereignisse in Modellkoordinaten (`clickPin`, `clickWire`, `clickEmpty`, `pressPart`, `dragTo`, `release`) und haengen sich mit `attach(view)` an – alle angehaengten Ansichten werden nach jeder Aenderung neu gezeichnet.
- **`editor.js` ist jetzt nur noch SVG-Renderer**: Hit-Testing, Bildschirm→Modell-Umrechnung, Einpassen (`fit`), Zeichnen. Die bisherige API (`ed.layout`, `ed.sel`, `ed.tool`, `ed.probes`, `addPart`, `removeSelected` …) leitet an den Kern weiter, `app.js` bleibt unveraendert. Ein gemeinsamer Kern kann per `new DQEditor(svg, { core })` uebergeben werden (Grundlage fuer `bench.js`).
- QA: Engine-Tests 43 gruen (inkl. 10 neue Kern-Tests ohne DOM), Validator 0 Fehler, Browser-Durchlauf OK, Bedienung (Ziehen/Drehen/Esc) im Browser gleich wie vorher.

## Werkbank-Umsetzung – Phase 2 erledigt (28.09.2026)
- **`dev/src/bench.js` (`window.DQBench`)**: 2.5D-Werkbank als zweiter Renderer ueber demselben Kern. Laborunterlage auf Holztisch, fester Blickwinkel (Szene in y um K = 0,8 gestaucht), Bauteile als Praktikums-Steckbausteine mit 4-mm-Buchsen, Verbindungen als Laborkabel mit Bananensteckern (Durchhang, Schatten; Pluspol rot, Minuspol/Masse schwarz, sonst Farbe nach Reihenfolge). Illustriert: Batterie (9-V-Block, Wert aufgedruckt), Widerstand (Farbringe aus dem Wert), LED (Farbe, Leuchten), Lampe (Gluehen), Schalter (Kippschalter 0/I), Taster; einfache Bausteine fuer Diode, Kondensator, Strommesser, Poti, Taktgeber, Gatter (DIP-Chip), Masse. Durchgebrannt wird angezeigt. Messspitzen erscheinen vereinfacht (echtes Multimeter = Phase 4).
- **Voll interaktiv**: Bausteine ziehen/drehen/loeschen, Kabel stecken (auch mehrere pro Buchse), Schalter/Taster betaetigen, Messspitzen setzen – alles ueber den Kern, eigenes Hit-Testing (gleiche data-Attribute wie im Schema).
- **Kern mit zwei Koordinatenraeumen**: `circuit-ui.js` kennt 'schema' (`p.x/p.y/p.rot`) und 'bench' (`p.bench = {x, y, rot}`, Raster 10, 1200 × 760). Ziehen/Drehen auf der Werkbank aendert nur die Werkbank-Lage. `p.bench` wird mit dem Entwurf gespeichert (Engine ignoriert das Feld).
- **`bench`-Layout pro Aufgabe** wird beim Laden uebernommen, auch fuer spaeter hinzugefuegte Bauteile mit passender ID (z. B. R1 landet am vorgesehenen Platz). Ohne Eintrag: Auto-Anordnung aus der Schema-Lage (Uebergangsloesung). Die Beispielaufgaben 1.1–1.3 haben ein `bench`-Layout. `validate.js` prueft es (ID aus start/ref, keine Doppelten, x/y, rot 0/90/180/270; Warnung bei Startbauteil ohne Lage).
- **App**: ein gemeinsamer `DQCircuit`, Schema und Werkbank haengen daran. Ansicht vorlaeufig per `index.html?werkbank` oder `DigitalQuest.setView('bench'|'schema')` (sichtbarer Umschalt-Button = Phase 5). Palette, Drehen, Einpassen wirken auf die aktive Ansicht.
- QA: 49 Tests gruen (inkl. 6 neue zum Werkbank-Raum), Validator 0 Fehler, Browser-Durchlauf OK inkl. neuem Werkbank-Teil (1.1 auf der Werkbank bauen + pruefen, 1.2 bauen + LED-Spannung messen + pruefen; Screenshots `6_werkbank_lampe.png`, `7_werkbank_led.png`), Handy ohne horizontalen Scroll.
